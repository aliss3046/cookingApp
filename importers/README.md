# importers/ — Python

Импорт рецептов и разбор ингредиентов. Связь с Go API только через базу (таблица `jobs`),
см. [ADR-0006](../docs/adr/0006-go-api-python-workers.md).

## Что есть

| Модуль | Назначение |
|---|---|
| `quantities.py` | Числа в строках рецептов: `2`, `1,5`, `1/2`, `1 1/2`, `½`, диапазоны `2-3` |
| `units.py` | Единицы (г, кг, мл, л, ст. л., ч. л., стакан, щепотка, зубчик, пучок, шт и др.) и перевод в г/мл/шт |
| `ingredient_line.py` | `parse_line("2 ст. л. масла")` -> название, количество в базовых единицах, единица |
| `text.py` | Токены и простой стеммер: «моркови» и «морковь», «перца» и «перец» дают одну основу |
| `directory.py` | Справочник ингредиентов (`db/seeds/ingredients.json`, 332 позиции) и `match(name)` |
| `draft.py` | `build_draft(...)`: строки -> черновик рецепта на порцию по схеме `RecipeInput` |
| `recipe_page.py` | Импорт по ссылке: загрузка с проверкой robots.txt, разбор schema.org/Recipe, черновик |

Не сделано: разбор через LLM для строк, которые не прошли правила; запись черновика в базу
(это вызывает воркер через таблицу `jobs`, после появления портов на Python).

## Справочник ингредиентов

`db/seeds/ingredients.json`: `id` (латиницей, стабильный, в базе это `ingredients.external_ref`),
`name`, `synonyms`, `group`, `piece_weight_g` — вес «штуки», в которой продукт продаётся
(головка чеснока 50 г, пучок укропа 30 г, банка кукурузы 340 г), `unit_weights_g` — вес других мер
(зубчик чеснока 5 г, веточка укропа 2 г, ломтик хлеба 30 г).

**Веса взяты как типичные средние значения и требуют проверки владельцем проекта** до загрузки в базу.

Сопоставление: псевдоним подходит, если все его значимые слова есть в названии из рецепта; побеждает
самый длинный («сливочное масло» точнее «масла»). Ничья между разными ингредиентами — строка
`needs_review` с причиной `ambiguous` и кандидатами для выбора парой. Тест проверяет, что у разных
ингредиентов нет псевдонимов с одинаковыми основами.

## Черновик рецепта

- Количество делится на число порций из `recipeYield`; если его нет — 1 порция и предупреждение.
- Зубчик, веточка, ломтик переводятся в граммы через `unit_weights_g`; если веса меры нет — `unit_unknown`.
  Головка, пучок, банка, пачка, бутылка и «шт» остаются штуками продукта.
- «Соль, перец — по вкусу» делится на две необязательные строки.

## Допущения

- г и мл считаются равными (1 мл ≈ 1 г), плотность не используется (как в расчёте корзины).
- Общие меры: стакан 200 мл, ст. ложка 15, ч. ложка 5, щепотка 0,5 г, горсть 30 г. Это приблизительные значения;
  уточнение под продукт (соль тяжелее воды) должно идти через справочник ингредиентов.
- `parse_line` считает банку, пачку, зубчик, головку, ломтик штуками; в черновике зубчик, веточка и ломтик
  переводятся в граммы через справочник (см. «Черновик рецепта»).
- Диапазон `2-3` даёт верхнюю границу и флаг `approx`: лучше купить с запасом, чем не хватить.
- Строка без количества и без «по вкусу» не теряется: `needs_review` с причиной `no_quantity`.
  «Соль, перец — по вкусу» оставляет в названии оба продукта: разделять их должен справочник.

## Запуск

```bash
pip install -r requirements-dev.txt
pytest --cov=importers --cov-branch
ruff check . && ruff format --check .
```

## Качество

На корпусе из 20 рецептов (`tests/importers/fixtures/recipes.json`, 137 строк) без проверки разбираются 99,3% строк;
на проверку уходит одна строка без количества («Красный перец чили»). С сопоставлением со справочником
без проверки остаётся 98,6% строк черновика (140 после разделения списков): добавляется «Масло для жарки» —
неоднозначно, сливочное или растительное. Корпус составлен авторами правил,
поэтому цифра показывает отсутствие регрессий, а не качество на реальных сайтах: проверку нужно повторить
на реальных страницах рецептов через `import_recipe`.
