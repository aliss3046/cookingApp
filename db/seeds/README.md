# db/seeds/ — данные для загрузки в базу

Загружает в базу разработчик БД (миграции и загрузка не входят в Python-часть).

| Файл | Что это | Откуда |
|---|---|---|
| `ingredients.json` | Справочник ингредиентов, 335 позиций | пишется вручную |
| `recipes_source.json` | Стартовые блюда обычными строками («Говядина — 500 г») | пишется вручную |
| `recipes.json` | Те же блюда в структурном виде: ингредиенты из справочника, количества на порцию в г/мл/шт | **генерируется**, руками не править |

```bash
python -m importers.seed_recipes          # пересобрать recipes.json из recipes_source.json
python -m importers.seed_recipes --check  # проверить, что файл не отстал (то же делает CI)
```

Сборка строгая: если хоть одна строка не разобрана или не сопоставлена со справочником, она падает с
перечнем проблем. Так в базу не попадёт блюдо с потерянным ингредиентом.

## Что нужно проверить владельцу проекта до загрузки в базу

Количества и веса написаны мной по типичным домашним рецептам, их никто не сверял. План требует
просмотра владельцем до загрузки. Что смотреть:

1. **Количества в `recipes_source.json`** на указанное число порций (42 блюда). Ошибка там тиражируется в корзину.
2. **Вес штуки и мер в `ingredients.json`** (`piece_weight_g`, `unit_weights_g`): от них зависит перевод
   «3 зубчика» и «2 луковицы» в граммы и сравнение цен весовых и поштучных товаров.
3. **Теги**: словарь закрытый (см. `tests/importers/test_seed_recipes.py`), новые теги добавляются там же.

## Формат `recipes.json`

```json
{
  "slug": "borsch",
  "title": "Борщ с говядиной",
  "default_servings": 6,
  "tags": ["обед", "суп", "мясо"],
  "status": "confirmed",
  "ingredients": [
    {"ingredient_id": "beef", "qty_per_serving": 100.0, "unit": "g", "optional": false,
     "raw_text": "Говядина на кости — 600 г"}
  ]
}
```

`ingredient_id` — `id` справочника (в базе это `ingredients.external_ref`, при загрузке переводится в uuid).
Необязательные строки («соль — по вкусу») имеют `qty_per_serving: 0` и `optional: true`: в корзину они не попадают.
`slug` — стабильный идентификатор блюда для повторной загрузки без дублей.
