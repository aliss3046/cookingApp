# Магазины: условия использования и адресация

Статус: **не проверено**. Это задача Фазы 0, выполняется до любого кода сбора.
Пока в этом файле нет записи «разрешено», `stores.collection_enabled = false`.

## Что нужно зафиксировать для каждого магазина

1. Как задаётся адрес доставки: cookie, параметр URL или заголовок.
2. Как листаются страницы каталога.
3. Что сказано в `robots.txt` для каталога.
4. Что сказано в условиях использования сайта о автоматическом сборе.
5. Вывод: сбор разрешён / запрещён / неясно. При «запрещён» и «неясно» провайдер работает
   только на ручном вводе и чеках.

## Дикси (dixy.ru)

Известно из плана: сайт на Bitrix, цены в HTML (рубли и копейки раздельно), скрытого JSON API
в каталоге не видно, цена и ассортимент зависят от адреса.

| Пункт | Результат |
|---|---|
| Адрес (cookie/параметр) | _не проверено_ |
| Пагинация | _не проверено_ |
| robots.txt | _не проверено_ |
| Условия использования | _не проверено_ |
| Вывод | _не проверено_ |

Подход при разрешении: httpx + BeautifulSoup; если адрес не воспроизводится cookie — Playwright.

## Ручной ввод и чеки

Резервный провайдер, не зависит от сайтов. Цена вносится вручную или из чека
(`prices.source = manual | receipt`).

## Нормализация цен и количеств (спецификация)

| Вход | Результат |
|---|---|
| «129 99 ₽» (рубли и копейки раздельно) | `129.99` |
| «0.5 кг» | `500 g` |
| «1 л» | `1000 ml` |
| «цена за 1 кг» | отдельное поле `price_per_kg` |

## Эксплуатация

Запуск раз в сутки (GitHub Actions или Fly.io), пауза между запросами, кэш по паре
(товар, адрес). Алерт, если число разобранных товаров упало больше чем на 30% относительно
прошлого запуска (признак смены вёрстки). Парсеры тестируются на сохранённых HTML.
