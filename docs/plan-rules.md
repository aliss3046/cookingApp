# План недели: день, приём пищи, предупреждения

Статус: на согласование. Реализация: `domain.PlanItem.Validate`, `suggest.Conflicts`.

## День и приём пищи

Блюдо плана (`plan_items`) может иметь `date` и `meal` (`breakfast`, `lunch`, `dinner`, `snack`).

| Случай | Поведение |
|---|---|
| Нет даты и приёма пищи | Допустимо: «на неделю, день не выбран» (например, заготовка впрок) |
| Дата без приёма пищи | Допустимо |
| Приём пищи без даты | Ошибка `validation_failed` |
| Дата вне недели плана (`week_start` .. `week_start + 6`) | Ошибка `validation_failed` |
| Порций меньше 1 | Ошибка `validation_failed` |
| Несколько блюд в один день и приём пищи | Допустимо (основное и салат) |

Время в дате отбрасывается, сравниваются календарные дни.

## Предупреждение о чужом «не хочу»

Добавить в план блюдо, за которое кто-то из пары проголосовал «не хочу», **можно**: решение за парой.
Но у такого блюда в ответе есть `conflicts` со списком участников. Предупреждение приходит:

- в ответе на `POST /plans/{id}/items`;
- в `GET /plans/{id}/items` (голос мог измениться после добавления блюда).

Блюдо с конфликтом в `GET /plans/{id}/suggestions` не попадает вообще.

## Что не решено

- Блюда плана никак не связаны по приёмам пищи с КБЖУ или бюджетом дня (отложено).
- Копирование недели целиком («как на прошлой») в API не предусмотрено.
