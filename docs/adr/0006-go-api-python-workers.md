# ADR-0006: Go для API, Python для воркеров

Статус: принято (заменяет часть ADR-0001 про язык API и расчёта корзины)

## Решение

**Go** отвечает за то, что работает по запросу пользователя и должно быть быстрым,
предсказуемым и строго типизированным. **Python** отвечает за работу с внешним неструктурированным миром:
чужие сайты, текст, эвристики «что подобрать».

| Go: `api/` | Python: `prices/`, `importers/`, `recommend/` |
|---|---|
| HTTP API `/v1` по OpenAPI | Парсеры магазинов, нормализация цен |
| Расчёт корзины: порции, склейка, запасы, исключения, упаковки, итог по магазинам | Импорт рецептов: JSON-LD, разбор строк ингредиентов (правила + LLM) |
| Голосование и пересечение пожеланий пары | Подбор товара под ингредиент с уверенностью |
| Постановка тяжёлых задач (`jobs`) и выдача статуса | Рекомендации: стартовые рецепты, позже «из остатков» и ранжирование |
| | Расписание сбора цен, алерты |

## Связь между частями

Go и Python **не вызывают друг друга напрямую**, связь идёт через базу:
Go создаёт строку в `jobs` и отвечает `202`, Python-воркер забирает задачу, пишет результат
(`prices`, `ingredient_product_map`, `recipes`) и обновляет статус в `jobs`, клиент узнаёт об этом
через Realtime или `GET /jobs/{id}`.

## Связь с базой: порты

Логика не знает про SQL. Данные запрашиваются через интерфейсы:

- Go: `api/internal/ports` — интерфейсы репозиториев и `ErrNotFound`;
- Python: `Protocol` в `*/ports.py` каждого воркера.

Интерфейсы, доменные типы, фейки в памяти и логику пишет команда логики. Реализации на
Postgres (pgx/sqlc в Go, psycopg в Python), миграции и RLS пишет разработчик БД. Набор контрактных тестов
(`api/internal/ports/contracttest`) прогоняется и на фейке, и на Postgres-реализации:
если поведение расходится, тест падает. Изменение интерфейса порта делается только через PR,
который видят обе стороны.

`couple_id` всегда передаётся в методы порта явно (берётся из токена). Go подключается к Postgres
напрямую, поэтому RLS включается установкой `request.jwt.claims` в транзакции, а не обходится
сервисной ролью (окончательно согласовать с разработчиком БД).

## Граничные случаи

- Единицы: разбор текста в г/мл/шт делает Python. В базе рецепты уже в базовых единицах,
  Go пересчёт строк не нужен. Таблица пересчёта — общий JSON.
- Пересечение голосов — простое правило, поэтому в Go. Подбор и ранжирование — в Python.
- Источник правды для моделей — `docs/openapi.yaml` и `docs/schema.md`.

## Почему

Go даёт простую развёртку одним бинарником, строгие типы и быстрый HTTP. Для разбора HTML,
JSON-LD и работы с LLM лучшие библиотеки на Python. Связь через базу оставляет части
независимыми: каждая развёртывается и падает отдельно, воркеры можно запускать по расписанию
в GitHub Actions.

## Альтернативы

- Всё на Python (ADR-0001): один язык, но команда хочет Go для API.
- Всё на Go: парсинг HTML и LLM-разбор заметно сложнее.
- Внутренний HTTP/gRPC между Go и Python: второй контракт и связность при отказах.
