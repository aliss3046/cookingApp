# Корзина и сравнение цен: правила и граничные случаи

Статус: **на согласование** (до кода). Реализация: `api/internal/cart` (Go, чистые функции без БД и сети).

## Что делает система, а что нет

**Корзина** — это список продуктов под выбранные блюда (`cart_lines`). Заказ в магазине мы **не оформляем**. Мы:

1. по выбранным блюдам строим корзину (ингредиент + сколько нужно);
2. для списка получаем цены магазинов (воркер цен, Python);
3. показываем паре **где что дешевле** и сколько выйдет в каждом магазине.

Доставка в этой версии не считается.

```
План → Корзина (строки: ингредиент, нужное кол-во)
         → для каждой строки: марка (выбор пары) → предложения магазинов
         → Comparison: самый дешёвый магазин по строке, итоги по магазинам, рекомендация
```

## Единицы

- **г и мл считаются равными** (1 мл ≈ 1 г), плотность не используется. «200 г» и «100 мл» одного
  ингредиента складываются в 300.
- **Штуки в граммы не переводятся.** Потребность хранится в тех единицах, в которых её задал рецепт.
  Одна строка корзины может нести **две потребности сразу**: масса (г/мл) и штуки.
  Пример: лук 100 г в одном блюде и 2 луковицы в другом → `need = {mass: 100, pcs: 2}`.
- Остальные единицы (ложки, стаканы) приведены к г/мл ещё при сохранении рецепта.

## Как продаётся товар

Магазин продаёт один и тот же ингредиент по-разному. У товара есть **способ продажи**
(`sale_mode`), который определяет парсер:

| `sale_mode` | Пример | Что покупается |
|---|---|---|
| `pack_mass` | молоко 930 мл, мука 1 кг | упаковка фиксированной массы |
| `pack_count` | яйца 10 шт, пакет лимонов 4 шт | упаковка из N штук |
| `per_piece` | лук, лимон, огурец за штуку | любое целое число штук |
| `by_weight` | лук за 1 кг (цена за кг, шаг 0,1 кг) | любая масса с шагом |

## Сопоставление потребности и товара

Расчёт идёт отдельно для каждого товара, исходная потребность не меняется.

| Потребность | Товар | Что считаем |
|---|---|---|
| масса | `pack_mass` | `packs = ceil(mass / pack_mass)`, остаток в запасы |
| масса | `by_weight` | масса округляется вверх до шага (100 г), остатка нет |
| штуки | `per_piece` | `pcs` как есть |
| штуки | `pack_count` | `packs = ceil(pcs / N)`, остаток в штуках |
| штуки | `pack_mass`, `by_weight` | нужен вес штуки ингредиента (`piece_weight_g`): тогда считаем по `pcs × piece_weight_g` и помечаем предложение `estimated = true`. Веса нет → предложение `unit_mismatch`, цена не считается |
| масса | `per_piece`, `pack_count` | то же через `piece_weight_g`, `estimated = true`; веса нет → `unit_mismatch` |
| масса + штуки | любой | обе части приводятся к единице товара через `piece_weight_g` (`estimated = true`); веса штуки нет → `unit_mismatch` (частично покрытых предложений нет) |

`estimated` значит «цена приблизительная»: вес штуки взят из справочника, а не из магазина.
Такое предложение не скрывается, но в «самый дешёвый» попадает только после точных.

## Шаги расчёта корзины (порядок важен)

1. **Порции.** `qty_per_serving × servings` по каждому блюду плана.
2. **Склейка.** Ключ — `ingredient_id`. Масса (г и мл) суммируется вместе, штуки отдельно: получается `need = {mass, pcs}`.
3. **Исключения.** Строки с `excluded = true` и `optional = true` в корзину не попадают.
4. **Запасы.** `need = max(0, need − pantry)`. Если `need = 0`, строка помечена `covered`.
5. **Ручные позиции.** Попадают в корзину как есть, без пересчёта и без предложений.

## Марка (производитель)

Нужен товар без выбора: у молока десятки марок. Правило:

| Ситуация | Поведение |
|---|---|
| У пары уже сохранена марка для ингредиента | Используем её автоматически, показываем «выбрано: <марка>», кнопка «сменить» |
| Сохранённой марки нет, в магазинах 1 марка | Берём её, сохраняем как выбор по умолчанию |
| Сохранённой марки нет, марок 2 и больше | Статус `choose_brand`: отдаём паре список марок с минимальной ценой каждой; **пара выбирает**, выбор сохраняется |
| Пара меняет марку позже | Новый выбор перезаписывает старый и действует на будущие списки |
| Сохранённой марки нет в одном из магазинов | У этого магазина статус `brand_missing`; показываем ближайшие по цене другие марки как **альтернативу**, но молча не подставляем |
| Сохранённая марка нигде не найдена | Строка возвращается в `choose_brand` |

Марка привязана к паре и ингредиенту, а не к одному магазину: «Простоквашино» одинакова в Дикси и Ленте.

## Предложения и сравнение

Для строки и выбранной марки каждый магазин даёт предложение: товар, число упаковок, стоимость,
остаток, цена за базовую единицу, признаки (`stale`, `in_stock`, `store_only`).

- **Упаковки.** `packs = ceil(need / pack_qty)`, остаток `packs × pack_qty − need` предлагается записать в запасы (`leftover`). Платим за целые упаковки.
- **Самый дешёвый по строке** — минимум стоимости среди предложений, которые в наличии, не `store_only`.
- **Итог по магазину** — сумма его предложений по строкам, которые магазин покрывает; рядом число не покрытых строк.
- **Рекомендация.** Отдаём два варианта: (а) самый дешёвый магазин, **покрывающий всю корзину**; (б) «разнести по магазинам» — по каждой строке самый дешёвый, с общей суммой. Сравнивать магазины с разным покрытием по голой сумме нельзя, поэтому покрытие показывается всегда.
  Итоги магазинов сортируются так: сначала закрывающие всю корзину, затем по сумме. Приблизительные
  предложения (`estimated`) в итог магазина входят и помечены флагом `HasEstimated`, поэтому «самый дешёвый магазин»
  может опираться на оценку, а выбор по строке (`Cheapest`) всегда предпочитает точное предложение.
- **Запасы в другой единице** (запас в штуках, нужна масса) не вычитаются: молча ничего не пересчитываем,
  возможна лишняя покупка.

## Граничные случаи

| № | Случай | Поведение |
|---|---|---|
| 1 | г и мл одного ингредиента в разных блюдах | Суммируются как одно |
| 2 | Потребность в штуках, товар только на вес, веса штуки в справочнике нет | Предложение `unit_mismatch`, цена не считается; пара видит товар, но не сумму |
| 2а | Потребность в штуках, вес штуки известен, товар на вес | Считаем `pcs × piece_weight_g`, `estimated = true` |
| 2б | Потребность и масса, и штуки (100 г + 2 шт лука) | `need = {mass: 100, pcs: 2}`; товар `per_piece` покрывает штуки точно, массу через вес штуки (`estimated`) |
| 2в | Лук продаётся и на вес, и поштучно | Оба варианта показываем как отдельные предложения, сравниваем после приведения к одной базе |
| 2г | Яйца 10 шт, нужно 12 | 2 упаковки, остаток 8 шт в запасы |
| 2д | Лимон поштучно, нужно 3 | 3 штуки, остатка нет |
| 3 | Нужно меньше одной упаковки (300 г из 500 г) | 1 упаковка, остаток 200 г |
| 4 | Нужно 700 г, упаковка 500 г | 2 упаковки, остаток 300 г |
| 5 | Нужно ровно кратно упаковке | Остаток 0 |
| 6 | Запасов хватает | `covered`, предложений нет |
| 7 | Запасов больше, чем нужно | `need = 0`, в минус не уходит |
| 8 | Товар `by_weight` (цена за кг, шаг 0,1 кг) | Масса округляется вверх до 100 г, цена = `price_per_kg × кг`, остатка нет |
| 9 | Товар «только в магазине» (`store_only`) | Предложение показываем, помечаем, в «самый дешёвый» не берём |
| 10 | Нет в наличии | Предложение показываем, помечаем, в «самый дешёвый» не берём |
| 11 | Цена старше 3 дней | Остаётся с `stale = true`, цену не скрываем |
| 12 | Нет сопоставления ингредиента с товарами | Статус `no_offers`; пара может добавить продукт вручную |
| 13 | Строка с неразобранной единицей (`needs_review`) | Количество не считаем, строку отдаём как есть (`raw_text`) |
| 14 | Нужно несколько марок (пара выбрала разные для разных блюд) | Не поддерживаем: одна марка на ингредиент |
| 15 | Ни у одного магазина нет цены на строку | Строка в корзине, `no_offers`, в суммы не входит |
| 16 | Один магазин не покрывает половину корзины | Его итог показан вместе с числом непокрытых строк |
| 17 | Ручная позиция | Попадает в корзину, в сравнение не участвует |
| 18 | Пустой план | Пустая корзина, итоги нулевые |

## Правки пары: количество, свои продукты, закреплённый товар

Корзина пересчитывается из плана, поэтому правки хранятся в `cart_lines` и накладываются поверх расчёта
(`Input.ApplyLines` переносит сохранённые строки во вход `Build`).

**Количество.** Пара может задать своё количество строки. Оно *заменяет* расчётное (`qty_overridden`):
запасы к нему не применяются, потому что пара сама сказала, сколько ей нужно. Единица может быть другой
(расчёт был в граммах, пара задала штуки). Количество 0 делает строку `covered`. Если ингредиента уже нет
в корзине (убрали блюдо) или единица неверна, правка игнорируется.

**Свой продукт.**

| Позиция | Поведение |
|---|---|
| Без привязки к ингредиенту (свечи, салфетки) | Лежит в корзине как есть, без цен и сравнения |
| С привязкой к ингредиенту | Склеивается с этим ингредиентом: количество *прибавляется* к блюдам (до вычета запасов), строка получает предложения и участвует в сравнении. Вклад ручной позиции виден в `FromManual` |
| Привязка к ингредиенту, который пара убрала из корзины | Исключение относится к блюдам; ручная позиция остаётся |
| Привязка и заданное количество | Заданное количество заменяет сумму блюд и ручной позиции |
| Ручная позиция, отмеченная исключённой | Не попадает в расчёт |

**Закреплённый товар.** Пара может закрепить конкретный товар (например, другую фасовку молока).
В *его магазине* остаётся только он, остальные магазины считаются как обычно, поэтому закрепление не заставляет
покупать именно там: «самый дешёвый» по-прежнему определяется ценой. Закреплённый товар задаёт и марку,
он важнее сохранённого выбора марки. Если товар закончился, он остаётся в списке с пометкой и магазин считается
непокрытым. Если товара уже нет в каталоге, закрепление игнорируется.

## Что не входит в эту версию

Доставка и порог бесплатной доставки, акции и цена по карте (поле отдаём, в сравнение идёт обычная
цена), оформление заказа, несколько марок на один ингредиент.
