# cookingApp

Бэкенд приложения для пары: вместе выбирать блюда на неделю и получать общую корзину
с ценой и доставкой из магазинов (Дикси, Лента).

Статус: **Фаза 0 — Архитектура** (кода логики пока нет, ждём принятия документов владельцем).

## Структура

| Путь | Назначение |
|---|---|
| `frontend/` | Место для клиента. Пишет другой разработчик, бэкенд-агент сюда не лезет |
| `docs/` | Архитектура, схема БД, ADR, контракт OpenAPI, выводы по магазинам |
| `db/` | Миграции и сиды (справочник, стартовые рецепты) |
| `api/` | **Go**: HTTP API, расчёт корзины, голосование, порты к БД |
| `prices/` | **Python**: провайдеры магазинов и воркер цен |
| `importers/` | **Python**: импорт рецептов, разбор ингредиентов |
| `recommend/` | **Python**: рекомендации блюд |
| `tests/` | Юнит-тесты, фикстуры, мок-сервер для фронтенда |

## Порядок работы

Документ → согласование → код. Фазы: 0 Архитектура, 1 Основа, 2 Ядро, 3 Цены.
Фаза закрывается, когда тесты проходят, документы обновлены, контракт совпадает
с реализацией и владелец принял результат письменно.
